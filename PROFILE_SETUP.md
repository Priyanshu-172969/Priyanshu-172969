## 4. Contribution snake

The contribution snake is generated by the workflow:

`.github/workflows/contribution-snake.yml`

The generated light and dark SVG files are published to the `output` branch:

- `github-snake.svg`
- `github-snake-dark.svg`

To run it manually:

1. Open the profile repository.
2. Select **Actions**.
3. Open **Generate contribution snake**.
4. Select **Run workflow** and confirm.
5. Wait for the run to finish.
6. Confirm the run is green and both SVG files are present in the `output` branch.

The latest inspected run before this documentation update completed successfully. Recheck Actions after future workflow edits.

## 5. Safe local workflow (optional)

You do not need terminal commands to edit the profile. GitHub's web editor is enough for small changes.

If you prefer VS Code, create a clean local copy rather than overlaying another downloaded folder on top of an older copy:

```powershell
git clone https://github.com/Priyanshu-172969/Priyanshu-172969.git github-profile-clean
cd github-profile-clean
git status
```

Run these commands in a new folder where you want the clean copy to live. Do not run them inside an old folder whose contents or Git state you do not understand.

After editing:

```powershell
git add README.md PROFILE_SETUP.md assets .github/workflows/contribution-snake.yml
git commit -m "Update GitHub profile"
git push
```

Do not use `git push --force`, `git reset --hard`, or `git clean -fd` for this profile update.

## 6. Avoiding duplicate files

The README expects one canonical copy of every asset under `assets/`.

Before uploading a replacement asset:

1. Check whether the corresponding file already exists in the expected folder.
2. Replace that file if you are intentionally updating it.
3. Do not upload another copy to the repository root.
4. Check the README path before removing an old file.

This prevents the root-level and nested copies from drifting apart.
